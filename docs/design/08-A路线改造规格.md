# 08 · A 路线改造规格（工业舱：配置与取舍）

日期：2026-11-18　状态：**已确认方向（用户选 A）**，本文件是实施依据。

## 0. 前提与边界

| 项 | 决定 |
| --- | --- |
| `jar-system-dotnet` / `JarSystem.Core` | **只读**，本期不新增任何 API |
| 玩家直接操作罐子（倒液/改形/转移） | 本期不做（Core 无玩家级操作入口，属二期 B） |
| 场景结构 | 保持单屏射击 + 面板式工业舱，不改成空间化工作台 |
| 玩家能动性来源 | 选哪台 / 投多少 / 接哪单 / 何时开始 / 何时取消 |
| Solver 定位 | **报价与提示**，不是执行者，也不假装是唯一答案 |

硬规则（沿用 03 §0）：界面只展示 Core 给的字段，不翻译业务语义、不解析错误字符串做判断、不在 GDScript 里重算规则。

## 1. 六步决策流程与现状对照

| 步骤 | 玩家做什么 | 现有 UI | 差距 |
| --- | --- | --- | --- |
| 1 选工作台 | 选主台/副台 | `BenchCard` 的「换主台 / 换副台 / 撤掉副台」 | 无（但执行中应禁用） |
| 2 配置资源 | 调档位、投矿 | `LinesPanel` 档位按钮 +「投矿 +0.2」 | 无（但执行中应禁用） |
| 3 选订单 | 选模板 / 随机派单 | `OrdersPanel`「选模板 / 随机派一单」 | 无（但执行中应禁用） |
| 4 看报价 | 判断这单值不值得做 | 有可行性、做法、进度 | **缺**：耗时估算、资源消耗、风险提示 |
| 5 决定开始 | 确认执行方案 | 「开始」 | **缺**：按钮语义不清（未说明"交给 Core 执行"） |
| 6 观察 | 看过程与结果 | 过程进度 + 记录栏帧流 | 无 |

## 2. 报价卡字段规格（本轮实施）

字段全部来自 `feasibilityResult`（`FeasibilityResultData` 12 键）与 `state`，**不做推断**：

| 报价字段 | 数据来源 | 缺失/不可用时的处理 |
| --- | --- | --- |
| 可行性 | `feasible` | 未检查时显示「待检查」 |
| 直接可用件数 | `directCount` / 需求条数 | 未检查不显示进度条 |
| 方案步骤 | `solverPath[].operation`（人读原文）+ `masterPath` 非空时前置一段「先迁移」 | 任一为 null 时跳过，不拼 `<null>` |
| 计时步数 / 不计时步数 | `solverPath[].type`：`MATCH` 不计时，其余计时 | 一律显示"步"，不显示"秒" |
| 预计耗时（刻） | **估算**：计时步数 × 每单位刻数（实测 2） | 标注「估算」，并在 05 号测试计划里登记为待验证 |
| 资源消耗 | `solverPath[].costLiquid` 汇总；B 类另加 `transferLiquids` | 无消耗则不显示该行 |
| 风险 | `masterPath` 非空（要先迁移）、`undetermined == true`（求解器未定） | 无风险不显示 |
| 玩家操作 | 「按此方案执行」+「删除」 | 执行中只留「取消」 |

**不显示的内容**：不显示 Solver 的搜索过程、不显示"最优"字样、不把 `solverPath` 说成唯一解。

## 3. 控制权状态机

```
准备阶段（phase == "setup"）
    ├── 可改：换主/副台、档位、投矿、派单、删除
    └── 可开始：status == 待执行 且 feasible
执行中（processes 里有 order_execution 的 running/blocked）
    ├── 禁止：换主/副台、档位、投矿、派单、删除（按钮禁用 + 文案说明）
    └── 允许：取消（Core 语义：已完成部分不回滚，订单按失败收尾）
```

执行中锁定的理由：Core 的过程在 Tick 里推进，中途换台会让"这一步用的是哪台"失去定义。锁定是**界面纪律**，不是新增规则。

## 4. 不可行原因两层解释

- **第一层（已有）**：`reason` 优先，退回 `blockage`，原样显示。
- **第二层（本轮补）**：由 `state` 字段推出的**检查清单**，不是解析原因文字：

| 检查项 | 判据（全部来自 state） |
| --- | --- |
| 主装配台是否已选 | `globalState.currentMaster == null` |
| 副装配台 | 需求需要迁移时（`masterPath` 非空）提示"需先迁移，副台必须已选" |
| 舱段数量 | `warehouse.jars` 与需求条数比较 |
| 工质 | `warehouse.liquids` 与需求里的 `liquid` 逐项比较 |
| 禁装工质 | 需求里的 `liquid` 是否出现在某工作台 `ban` |
| 阶段 | `phase != "setup"` |

清单只回答"检查哪里"，不承诺"改了就能做"。

## 5. 成长取舍（现状记录，本期不改）

| 成长 | 现在拿到 | 现在付的代价 | 问题 |
| --- | --- | --- | --- |
| 投矿提速 | 每条产线 +0.2 速率（上限 0.6） | 2 矿石（战斗里打碎残骸获得） | 矿石目前**唯一用途**，没有机会成本 |
| 材料强化 | 子弹伤害 +1（上限 +5） | 3 材料（工单结算） | 材料同样唯一用途 |

两条不改 Core 的候选（**待用户决定，未实施**）：

- **候选 1：矿石双用途** —— 矿石除了投矿，还能"应急维修"（战斗中回 1 点血）。这是新增战斗玩法，不是改 Core。
- **候选 2：材料双用途** —— 材料可换"本局一次性炮击"或"跳过一张工单"。同样不动 Core。

在做出取舍前，诚实记录：**当前成长是纯正向累积，没有机会成本**。

## 6. 三种验证订单（用数据文件，不改 Core）

新增 `data/industrial/world_tradeoff.json`（与 `world_sandbox.json` 并存，界面可通过 `start(world_path)` 选择），内含三张模板：

| 模板 | 需求 | 想验证的策略 | 观察点（人工） |
| --- | --- | --- | --- |
| **资源取舍**「两舱等料」 | 圆舱 + 方舱（同一台都能做，但主台一次只能装有限舱段） | 有限舱段先给谁 | 玩家是否会为了第二张单改主台 |
| **配置取舍**「异形换台」 | 三棱舱 + 装蜜舱（三棱只在副台基础标记里，蜜在主台被禁） | 主副台配置差异 | 玩家是否比较两台的能力而不是总用同一套 |
| **时间取舍**「长线工单」 | 3 件复杂需求 + `turnLimit` 收紧 | 等待生产 vs 立刻接单 | 玩家是否先看仓库再决定接单时机 |

判定标准（人工，不做自动断言）：是否出现"换台比较""因资源不足改单""主动等生产""看完报价再调配置"四类行为。

### 9.2 两个实现中发现的事实

1. **锁定的判据必须包含 `created` / `ready`**：`startOrder` 返回时过程可能还没到 `running`，只判 `running/blocked` 会让"刚点开始就能改配置"漏过去。现在判据是"过程在册且未终结"。
2. **不能靠"随机单"验证锁定**：4 刻预热后仓库常常已经够料，订单一次 `Tick` 就跑完（无过程可锁），这类断言会时红时绿。改为喂一份**带在册过程的合成状态快照**给 `_apply_state`，判据只依赖 `processes` 字段，稳定可测。

### 9.3 测试污染收口

`hud_feedback`、`capture_battle`、`ui_smoke`、`scene_switch`、`reward_smoke`、`save_smoke`、`full_loop`、`segment_smoke`、`ui_capture` 都会改 `/root/GameState`，而它在 `_exit_tree()` 里落盘 `user://player.cfg`。本轮给 `GameState` 加了 `var persist_wallet := true` 开关（测试置 false），并逐个脚本关闭落盘。**验证**：跑完 9 套测试后 `player.cfg` 不存在，截图里矿石 6 / 材料 0 / 攻击 Lv0 为干净初始态。

### 10.2 三张单各自证明什么

- **双线争料**：执行长单后它从 `直接可用 3 / 可行` 变成 `0 / 不可行`（抢同一批舱段）。
- **异形换台**：主台上要 `RESHAPE ×1`、耗蜜 1 份；换到禁蜜的副台后**无路径**（配置决定可行性）。
- **超长线**：开局与推两刻都 `direct 0/5`，必须持续攒到第 6 刻附近，而回合上限只有 8（时间是预算）。

### 10.3 报价"估算刻数"收敛为单一来源

`IndustrialPacing.TICKS_PER_UNIT`，注释写明是**实测经验值、非 Core 契约**，报价行带 tooltip；Core 改执行节奏时只改这一处。

### 10.4 测试隔离（本轮又修一次）

`--script` 环境其实**会**装载 autoload，之前的补丁只在"自己新建 GameState"的分支里关落盘，等于没关。现在两层收口：
1. `GameState.save_wallet()` 在 `DisplayServer.get_name() == "headless"` 时直接返回；
2. 测试仍显式 `persist_wallet = false`。
验证：10 套测试跑完后 `user://player.cfg` 不存在；带窗口启动工业舱后又正常写回。
