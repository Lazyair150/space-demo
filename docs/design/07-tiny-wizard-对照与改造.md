# 07 · tiny-wizard-demo 对照与改造

来源：`D:\godot\programs\github\tiny-wizard-demo`（Quiver 的《Tiny Wizard》房间制顶视角射击 demo + `docs/复刻指导书_V3_完整修订版.md`，4927 行）。
本文只记录**能迁移到 space-demo 的东西**，以及本轮真正落地的改动。参考项目只读，未改动其任何文件。

## 1. 它到底在教什么（提炼，不是复述）

指导书的价值不在"如何复刻一个 Isaac"，而在四条方法论：

1. **一局要有编排，不是无限量刷**：它的 10 间房按"安全区 → 两类敌人对比 → 数量压力 → 资源与钥匙 → 奖励箱 → 追踪型强敌 → 隐藏奖励"排布（指导书 §1.3）。每一间房回答一个问题：这间房教玩家什么？
2. **奖励必须改下一次行动**：金币是纯计数（作者自己列为待扩展），而钥匙→开锁箱、炸弹→破墙开新路、紫箭→伤害翻倍、心→续命。后四者都是"拿到即改变下一步能做什么"（§1.3、§8.1）。
3. **门槛-资源-回报**三段结构：钥匙房在锁箱房之前、炸弹房在需要破墙的房间之前。玩家先知道缺什么，再去找，再回来用。
4. **验收先于扩展**：§0.6 给"可玩性验收链路"，§0.7 给最小可玩闭环 M1–M6，§6 给逐条勾选清单。每阶段留一个可运行场景。

另外两条工程习惯值得照抄：数据与行为分离（`.tres` Resource）、信号解耦（`stats_changed` / `bullet_destroyed` / `door_entered`）。

## 2. 八个维度的对照

| 维度 | tiny-wizard | space-demo 现状 | 差距与结论 |
| --- | --- | --- | --- |
| 单局结构 | 10 房有分支、有隐藏房、有终点 | 无限波次（第 n 波 n+2 敌，射手概率随波升），无终点无段落 | 缺**节奏编排**。不必搬房间制，但要把"无限曲线"切成可命名的段落 |
| 奖励种类 | 金币（计数）、心、钥匙、炸弹、紫箭、半盾 | 矿石（战斗→工业提速）、强化材料（工业→攻击力） | 种类不算少，但都是**数值累积**，没有门票/消耗品 |
| 奖励目的性 | 每种奖励改变下一次行动的可行性 | 矿石/材料只改变数值上限，玩家没有"用在哪"的决策 | 核心差距：缺**选择**与**门槛** |
| 反馈强度 | 拾取即 HUD 变化 + 音效建议（§8.1 第一条） | 只有分数行文字变化，无提示 | 缺**即时反馈**（本轮补） |
| 目标可见性 | 门/箱子/敌人数量本身即目标 | 玩家不知道"再攒多少能升级" | 缺**目标提示**（本轮补） |
| 数据外置 | 数值在 `.tres`，换数值不改场景 | 敌人波次曲线写在 `Spawner.gd`，升级成本写在 `GameState.gd` 常量 | 可外置，但不是当前瓶颈 |
| 存档颗粒度 | §8.3-10 指出宝箱 `active` 要唯一 ID 才能落盘 | 工业侧走命令日志回放（可靠）；战斗侧只有最高分 + 钱包，波次/残骸不落盘 | 现状自洽（战斗是消耗品、工业是资产），不需立刻补齐 |
| 验收方式 | 人工链路 + 最小闭环里程碑 + 清单 | 172 项自动断言，缺"一局完整感"的人工验收条目 | 两类证据互补，不是替代 |

## 3. 转化到太空题材：设计补充（分级）

### 3.1 本轮落地（不改战斗平衡，只补反馈与目标）

- 战斗 HUD 增加**获得提示**：拾取矿石、结算材料时浮出「+N 矿石 / +N 强化材料」，1.2 秒淡出。
- 战斗 HUD 增加**目标提示**：`再攒 N 材料可升级攻击` / `材料足够：去工业舱升级攻击` / `攻击已满级`；并在有矿石时提示"可投矿提速产线"。
- 依据：指导书 §8.1 把"反馈"列为性价比最高的一步；§0.6 的可玩性验收第 3 条就是"HUD 立刻变化"。

### 3.2 待定（会改玩法节奏，需拍板）

- **A. 段落化波次**（已落地，2026-11-18，见 §5）：把无限波次切成「热身 → 压力 → 精英 → 喘息」四段循环，每段有名字与提示。**实现时去掉了"精英波掉密钥卡"**——那属于路线 B 的经济改动，会绕过工单发奖口径；本版精英波只放大敌人（血 3/5/7…、体型 ×1.45、分数 60），不发任何资源。
- **B. 补给舱门票**：精英波掉密钥卡，场上出现一个"补给舱"，用钥匙开，必给 3 矿石 + 1 材料（材料仍是工业侧唯一产出口？否——这会绕过工单结算，需要决定材料是否只从工业出）。代价：新场景 + 发奖口径要改，容易破坏"同一产品只发一次奖"的纪律。
- **C. 消耗品（炸弹式）**：矿石可换"一次性炮击"，清屏小范围。代价：新增按键/道具栏与冷却，战斗代码分支变多。

推荐顺序：A → （若 A 的精英波足够有趣）不做 B，把材料留在工业侧；C 最后。

### 3.3 不建议照搬

- 房间制/整格切场景：space-demo 是单屏无限场，搬运需重写摄像机、敌人容器与刷新逻辑，收益不抵成本。
- 完整 ECS、多人联机：指导书 §8.4 自己也列为"不建议"。

## 4. 本轮改动清单（代码）

| 文件 | 改动 |
| --- | --- |
| `scripts/Hud.gd` | 新增获得提示与目标提示两块 UI（运行时构建，不动 `Hud.tscn`）；连 `materials_changed` / `attack_changed` |
| `tests/hud_feedback.gd` | 新增 15 项断言：矿石/材料变化时提示文本正确、只报增量、目标提示随材料档位切换、满级文案、分数/波次行未回归 |
| `tests/capture_battle.gd` | 战斗 HUD 截图脚本（需要真实窗口），产出 `tmp/ui_capture/battle_0{1,2,3}*.png` |

### 4.1 实测结果

- `hud_feedback`：15 项 0 失败。开局目标提示为「再攒 3 材料可升级攻击（工业舱工单结算）」；拾取 2 矿石后变为「…　·　矿石 2：可投矿提速产线」；材料 3 时切到「材料够了：去工业舱升级攻击」；满级时「攻击已满级（6 点）」。
- 战斗 HUD 截图（`battle_02_ore.png` / `battle_03_material.png`）：顶部金色 `+2 矿石` / `+1 强化材料` 浮字，底行目标提示，左上角 `Score/矿石/攻击` 与右上角血量未受影响。
- 七套工业测试回归全过（35 / 26 / 48 / 12 / 17 / 19 / 15 = 172 项，0 失败），headless 启动 `--quit-after 120` 无 error。

### 4.2 测试污染修正

`hud_feedback` 与 `capture_battle` 都会改动 `/root/GameState`，而它在退出时会 `save_wallet()` 写 `user://player.cfg`。两个脚本现在都**先清档、读完复原再删档**，避免把测试数值写进玩家真实进度（本轮截图第一次拍到"攻击:6 已满级"就是上一版测试残留造成的）。

## 5. 路线 A 实现记录（段落化波次，2026-11-18）

### 5.1 段落表

| 段落 | 波次 | 刷怪 | 设计目的 |
| --- | --- | --- | --- |
| 热身 | 1, 5, 9, … | `1 + 循环数` 只追兵，无射手 | 熟悉走位，失败也不冤 |
| 压力 | 2, 6, 10, … | `2 + 2×循环数` 只，35% 概率出射手 | 考清怪效率与走位取舍 |
| 精英 | 3, 7, 11, … | `1 + 循环数` 只精英（血 `3 + 2×循环数`、速度 92、体型 1.45、分数 60） | 考爆发与闪避，给一个"看得见的硬点" |
| 喘息 | 4, 8, 12, … | 不刷怪，间隔 4 秒（其余段落 2 秒） | 留出整理/去工业舱的窗口 |

`GameState.segment` 持有当前段落名（数据在状态层，不在界面里）；HUD 的波次行变成 `Wave:3   精英`，精英段文字变红，并在段落切换时浮一句提示（「精英波：一只强化敌机」/「喘息：整理一下，或去工业舱」）。

### 5.2 自动验证

- 新增 `tests/segment_smoke.gd` **17 项**：第 1→5 波的段落名依次为 热身/压力/精英/喘息/热身；热身 1 只、压力 2 只、精英 1 只且 `max_hp≥3`、`scale>1.2`、`score_value>10`；喘息波刷怪数为 0。
- 全量回归 9 套共 **204 项** 0 失败（hud_feedback 15 / segment 17 / bridge 35 / runtime 26 / ui 48 / scene_switch 12 / reward 17 / save 19 / full_loop 15），headless 启动 `--quit-after 150` 无 error/leaked。
- 截图：`tmp/ui_capture/battle_04_elite.png`（红字精英段 + 提示 + 放大敌机）、`battle_05_rest.png`。

### 5.3 仍未验证

- 难度曲线本身（"第 2 循环的压力波会不会太挤"）需要真人试玩，自动断言只能证结构，不能证手感；
- 精英敌机用的是 `EnemyChaser` 加数值，不是独立行为（不会冲刺、不召唤），行为差异化留给后续；
- 段落长度固定为 1 波，若之后想让某些段落更久，需要把 `segment_for_wave` 换成段落表驱动。
