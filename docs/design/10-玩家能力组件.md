## 3. 穿透弹实验：能不能只加组件？

### 做法

新增（未改 `Player.gd`、未改 `PlayerFeatures.gd`）：

- `scripts/player/features/PiercingShot.gd`：`extends PlayerFeature`，`@export pierce_count := 1`；`_ready` 里连 `get_tree().node_added`，事件到达时若自身 `active` 且节点像子弹，就 `set("pierce_count", n)` 并染色。
- `scenes/player/features/PiercingShot.tscn`：Scene + 脚本。
- `scripts/PlayerBullet.gd`：加 `@export pierce_count := 0`（默认 0 = 一碰即消，行为不变）、加入 `player_bullet` 组、命中记录按 `instance_id` 去重、次数用尽才 `queue_free`。
- `project.godot`：新增输入 `pierce = P`。

### 结论

**能加，但接口确实缺东西。**

- 缺的：现接口只有 `on_attack(player)`，拿不到"这一发子弹"；也没有命中回调，拿不到"打到了谁"。所以穿透只能靠监听**全场景**的 `node_added` + 鸭子类型 (`has_method("_try_hit")`) 补挂，还要把"穿透"这个语义塞进子弹自己的属性里。
- 这个绕道有真实代价：①每次任何节点入树都会回调一次（目前量小，但属于全局监听）；②命中结果对能力不可见 ⇒ 暴击/吸血/命中触发特效（审查说未来会不够的那类）**做不了**，除非子弹自己变成能力的一部分；③能力与子弹的耦合靠属性名约定，改名即断。

### 建议的下一步（未实施）

等真正要做**暴击/吸血/命中反馈**时再加一层上下文，而不是现在写满：

```
on_attack(player, AttackContext)        # 暴露这一发子弹/伤害来源
try_block_damage / on_hit(HitContext)   # 命中结果、目标、伤害数值
```

触发条件写清楚：只有当某个能力需要**读命中结果**或**修改这一发子弹**时才加；只改外观/开关的能力用现有四接口足够（护盾、双发、穿透已验证）。

## 4. 已知边界

- 护盾无敌 `0.5s` 是经验值，没做真人节奏验证；
- 三个能力默认全关，玩家要按 K/L/P 才有，且**首次进入没有教学提示**；
- `scenes/player/Player.tscn` 是同一玩家的第二份场景（未被任何场景引用，且里面 `EnergyShield` 节点没有脚本、子节点叫 `Sprite2D` 而不是 `Visual`），属于会误导后续编辑的重复文件，**尚未处理，等用户决定删除还是作为新家**；
- 穿透染色是 `modulate` 一次性设置，子弹自己的视觉逻辑若以后改调色会被覆盖。
